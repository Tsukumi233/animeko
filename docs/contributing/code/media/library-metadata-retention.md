# 资源库元数据保留

已确认的 `library_episode_binding` 使关联条目及其已知剧集缓存成为离线播放所需数据。
`SubjectCollectionDao` 的删除事务保留这些条目的公开名称、简介、封面、评分统计、关联信息和剧集，
并把收藏类型设为 `NOT_COLLECTED`，清空个人评分、私密评论、个人标签及剧集收藏状态。
没有资源库关联的条目继续按外键级联删除。最后一个绑定移除后，后续清理可以正常删除缓存。
所有收藏分页、最近更新、计数和收藏名称/ID 查询都排除 `NOT_COLLECTED`；按 ID 读取仍可取得离线元数据。

成功刷新收藏分页使用 `invalidateCollectionPage`：隐藏旧分页里的保留条目，但不清空同一账号的评分与剧集进度。
这避免未在第一页返回的资源库条目丢失用户状态。普通删除收藏、账号切换或退出使用删除/清理事务。
剧集列表刷新与剧集缓存删除检查资源库关联，保留关联条目的所有已知剧集，包括服务端当前列表没有返回的 SP。
服务端 404、断网或刷新失败不改变公开缓存的可读性，`librarySubjectCollectionFlow` 使用这些缓存。

`CollectionCacheAccountGuard` 在网络请求前记录账号代次，并在缓存写入时重新校验。
生产环境的条目、剧集仓储及会话切换回调共享同一个实例；缓存写入与清理/新会话发布互斥，
旧账号在途响应不能在切换后重新写入评分或收藏状态。清理失败或取消时不发布新账号。
SessionManager 的新登录与退出，以及设置备份导入不同的 access-token 身份，都会通过这个过程。
无法根据不同的 token 证明同一账号，因此导入不同 token 采取清理用户状态的保守行为；完全相同会话的导入不清理。
普通 access-token 续期不清理元数据。续期发布时原子校验原 refresh token，防止旧请求覆盖已退出或更换的会话。

当前仓库没有绕过 DAO 清理这些表的全局缓存删除入口；数据擦除和数据库重建不属于离线缓存保留范围。
后续新增元数据清理应调用这些 DAO 操作，不应直接删除有资源库关联的条目行。
